# R09: durable recovery for the common Space/Room wizard

The common SpaceManagementPanel previously kept created IDs and setup intent only in memory. This adds an account/origin-bound private journal before the first createRoom POST. It complements Desktop49's owner-private Agent-room recovery and the separate Native owner-management CreateMatrix workflow; neither covers the common wizard's ordinary Space/public/privacy/topic options. Those existing protocols remain unchanged.

A random operation marker binds the original owner and a digest of the exact config/Agent-space/Project intent. It is an initial room state event, not a Matrix transaction ID or a server guarantee of createRoom idempotency. The raw SDK/Ruma request disables automatic retries for this non-idempotent POST. All disk IO runs on blocking workers; private directories/files, a retained cross-process lease, bounded reads and synced atomic replacement protect the journal. At most one unfinished creation per account is admitted.

A returned original room ID is persisted before linking/adoption. Reopening restores the original config and business intent, including Agent-space versus ordinary-space and original Project/parent IDs. Unknown outcomes block new creation. Find original creation queries current joined rooms and the opaque marker, then validates authoritative room state, creator, membership, privacy, encryption and kind. Automatic scanning is limited to128 rooms/30seconds at the UI; incomplete or ambiguous scans never prove absence or permit a new POST. The user can explicitly supply the original room ID for verification. Recovery does not create or join another room.

Finish setup only repeats links/adoption for those original IDs. The server's exact active Project/Room registration must be confirmed before marking completion. Sync may need to catch up after the raw one-shot creation request; incomplete setup retains the saved ID and can be retried. Success or a lost setup response does not discard the original pending record. Borrowed/late UI results are fenced by account/session, room context and request generation.

Stopping tracking requires an explicit warning/confirmation: the original remote object may exist and a later Create is a separate request. The uncertain record is archived first, never silently erased; late returned IDs update the original archive without replacing a newer operation. Archived unresolved records are bounded to32. This does not undo already accepted remote effects, delete rooms, revoke an in-flight request or imply external effects were rolled back.

Tests exercise real private files, reopen, original-ID preservation, cross-account/corruption/concurrent admission, cross-process lease ownership, explicit archival and late results. A real official-SDK HTTP fixture simulates an applied create followed by a failed response for ordinary Space, Agent Space and Project Room: a persisted intent exists before POST, failed journal storage sends no create, recovery finds the original object, foreign candidates are refused and createRoom is sent exactly once. Real wizard fixtures verify an unknown ID cannot enable Create and restores the original business kind; adoption-response tests reject wrong/inactive registrations. Final release checks are recorded in the PR.

No new crypto keys, SDK fork, credential fallback, model calls or live room creation is introduced by validation. Local fixtures do not claim real homeserver fault-injection/cross-platform UI qualification. Recovery remains conservative if the owner left, state/marker was changed, more than128 rooms need scanning or the server cannot answer; explicit review is required. Archive records live under the application data directory, outside media-cache eviction.
